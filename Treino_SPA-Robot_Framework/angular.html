AngularJS: ng-repeat, filtros e ng-if vs ng-show

Três cenários clássicos de automação em apps Angular antigas (ou modernas com os mesmos padrões). Cada um tem a sua armadilha de sincronização.

AngularJS nível médio

1 · Busca de clientes com filtro ng-repeat

A tabela é renderizada por ng-repeat e filtra à medida que escreve — sem recarregar a página. O número de linhas muda sem aviso.

clientes.html
NomeEmailCidade
{{ c.nome }}{{ c.email }}{{ c.cidade }}

{{ (vm.clientes | filter:vm.busca).length }} clientes

Objetivo do teste

  • Escrever "silva" no campo de busca
  • Esperar que a tabela mostre apenas 1 linha
  • Validar o contador "1 clientes"

Ajuda

Esperar o filtro aplicar

O filtro do AngularJS aplica-se num ciclo de digest — quase instantâneo, mas não sincronizado com o Selenium. Espere pela condição do resultado, não por tempo.

robot 
Input Text    css:input.campo-busca-clientes    silva
Wait Until Element Is Visible    xpath://tr[contains(@class,'linha-cliente')][contains(.,'Ana Silva')]    timeout=5s
\${linhas}=    Get Element Count    css:tr.linha-cliente
Should Be Equal As Integers    \${linhas}    1
Element Text Should Contain    css:p.contador-clientes    1 clientes
Cuidado com as interpolações {{ }}

Antes do Angular compilar a página, o HTML contém literalmente {{ c.nome }}. Se o seu teste apanhar texto nesse estado, falha. Espere sempre por um elemento já compilado (com texto real) antes de ler valores.

2 · ng-if vs ng-show — a armadilha clássica

Dois painéis com o mesmo aspeto visual quando escondidos, mas comportamento oposto no DOM. O ng-if remove o elemento da página; o ng-show apenas aplica a classe ng-hide.

painel-detalhes.html

Detalhes avançados

Este painel usa ng-show: continua no DOM quando escondido — inspect element e verá.

Objetivo do teste

  • Abrir "Ver pagamentos" e validar a tabela de pagamentos
  • Trocar para faturas e validar que pagamentos desapareceu do DOM (ng-if)
  • Com "Alternar detalhes" desligado, provar que o painel extra existe no DOM mas está invisível (ng-show)

Ajuda

Asserções certas para cada caso

ng-if: o elemento sai do DOM — use Page Should Not Contain Element. ng-show: o elemento fica com class="ng-hide" — Element Should Not Be Visible passa, mas Page Should Not Contain Element falha (e devia falhar!).

robot 
# ng-if — removido do DOM
Click Button    xpath://button[contains(.,'Ver faturas')]
Wait Until Element Is Visible    css:div.painel-faturas    timeout=5s
Page Should Not Contain Element    css:div.painel-pagamentos

# ng-show — presente mas oculto
Page Should Contain Element    css:div.painel-extra
Element Should Not Be Visible    css:div.painel-extra
Porque é que isto importa em Angular/Vue modernos

O mesmo padrão existe hoje: *ngIf / v-if removem o elemento; [hidden] / v-show apenas escondem. Saber qual o mecanismo evita asserts errados que passam sem testar nada — ou falham sem motivo.

3 · Lista de tarefas com ng-click

Adicionar e remover itens muda o DOM sem recarregar — e cada remoção invalida referências a linhas antigas.

tarefas.html
  • {{ t }}

{{ vm.tarefas.length }} tarefas

Objetivo do teste

  • Adicionar a tarefa "Correr a suíte de regressão"
  • Validar que aparece na lista e o contador subiu
  • Remover a primeira tarefa e validar o novo contador

Ajuda

Adicionar e validar
robot 
Input Text    css:input.campo-nova-tarefa    Correr a suíte de regressão
Click Button    xpath://button[contains(.,'Adicionar')]
Wait Until Element Is Visible    xpath://span[normalize-space()='Correr a suíte de regressão']    timeout=5s
Element Text Should Be    css:p.contador-tarefas    4 tarefas
Remover pelo contexto, não pelo índice

Remover "a primeira tarefa" por posição (//li[1]//button) funciona, mas quebra se a ordem mudar. Prefira ancorar no nome da tarefa — é o padrão que se mantém estável:

Click Element    xpath://li[contains(@class,'item-tarefa')][.//span[contains(.,'Revisar relatório')]]//button[contains(@class,'btn-remover')]
Wait Until Element Is Not Visible    xpath://span[normalize-space()='Revisar relatório']    timeout=5s
